🔑

No Accounts

Your identity is a local Ed25519 key pair. No sign-up, no password reset flow, no account lockout.

🔒

End-to-End Encrypted

Handshake uses ephemeral X25519 + HKDF + AES-GCM. Signaling is signed, transcript-bound, and replay-resistant.

🚫

No Central Platform

ConquerD has no account backend. Sessions are direct when possible, with optional community supernode relay.

🔗

Invite-Only

Peers connect by signed conquerd:// invites that are timestamped and expiry-checked.

1

Launch & Onboard

On first run, ConquerD generates a local Ed25519 identity and walks you through setting a display name and optional supernode address.

2

Create an Invite

Click + to generate a signed conquerd:// invite link. Share it with a trusted peer via any channel — links are timestamped and expiry-checked on both ends.

3

Connect

ConquerD tries direct QUIC first, then UDP hole punch, then supernode QUIC relay — automatic for most networks with no configuration required.

4

Communicate

Chat, voice, and file transfer are available immediately after handshake. Delivery states and connection quality display in real time.

Prerequisites

  • Rust toolchain — install via rustup.rs
  • Qt 6.x — via the Qt Online Installer (select Qt 6.8+, your platform kit)
  • CMake 3.5+ — bundled with Qt or installed separately
1

Clone

git clone https://github.com/ConquerD/ConquerD.git --recurse-submodules
cd ConquerD
2

Fetch Opus DNN weights (enables DRED & OSCE)

powershell scripts/fetch_opus_weights.ps1   # Windows
bash scripts/fetch_opus_weights.sh           # Linux / macOS
3

Point to Qt and build

# Windows (PowerShell) -- point to your Qt install
$env:QMAKE = "C:\Qt\6.8.3\msvc2022_64\bin\qmake6.exe"
# Linux / macOS:  export QMAKE=/opt/Qt/6.8.3/gcc_64/bin/qmake6

cd rust
cargo build -p conquerd-client --features qt-ui --release
4

Run

./run_client.sh    # Linux / macOS
run_client.bat     # Windows

Highlights

You Own the Entire Path

From identity to transport to updates, ConquerD is designed so your communication stays under your control.

🎙

Direct Voice First

Calls prefer direct QUIC peer-to-peer. If NAT blocks direct paths, ConquerD falls back to relay automatically.

💬

Chat Stored Locally

Chat history is stored in local SQLite on participant devices, with delivery states and signature verification.

👥

Rooms with SFU Relay

Group rooms support up to 32 participants using supernode SFU relay for room audio plus room chat and files.

🛡

Signed Release Updates

Updates are distributed via GitHub Releases and verified against an Ed25519-signed release manifest before the bundled installer applies them.

🎮

Browser Game Relay

Supernodes host browser games over WebTransport. Bundled demos (cursor relay, brick breaker, shared drawing) connect via game.relay.v1 directly inside the native client’s Nodes tab.

Capability Framework

Feature Modules

Peers exchange CAPABILITY_ANNOUNCE after handshake. Only the shared intersection is activated and invokable.

Negotiation Flow

  1. Both peers send CAPABILITY_ANNOUNCE descriptor lists
  2. Runtime intersects by feature id and major version
  3. Invocation uses CAPABILITY_INVOKE per feature id
  4. Trust gates enforce auth tier, consent, and quota

Namespaces and Trust

  • First-party modules use core.* and room.* namespaces
  • Third-party modules use x.<vendor>.* versioned IDs
  • Per-feature token bucket quotas apply per peer
  • Trust checks run before module on_invoke handlers

Security and Compliance

Code Signing Policy

Binary code signing is being set up for release builds. During the alpha, builds are distributed unsigned with an Ed25519-signed release manifest as the root of trust.

ConquerD is currently in its 1.0.0-alpha testing phase. Alpha builds on the nightly release are not yet code-signed, so Windows SmartScreen or macOS Gatekeeper may warn before launch. Every release is published alongside a per-platform SHA-256 checksum and an Ed25519-signed release manifest that the bundled installer verifies before applying any update.

After alpha testing stabilises, release builds will be code-signed: Windows via SignPath.io (certificate by SignPath Foundation) and macOS via the Apple Developer Program. The Ed25519 release-manifest key remains the canonical root of trust across all platforms.
